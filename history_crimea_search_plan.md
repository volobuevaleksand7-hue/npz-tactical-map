# План поисковых запросов для агента HISTORY-CRIMEA

## Выполненные действия
1. Прочитан текущий файл `data/history-crimea.json` для понимания структуры и существующего контента
2. Определены необходимые поисковые запросы согласно заданию

## Необходимые поисковые запросы (4-6 запросов)
Согласно заданию, нужно выполнить следующие WebSearch-запросы:

1. `"НПЗ удар дрон октябрь 2026"`
2. `"Russian refinery drone strike resumed repaired"`
3. `"дефицит бензина Крым талоны 2026"`
4. `"Крым топливо трасса Новороссия"`

## Дополнительные рекомендуемые запросы (опционально, до 6 всего)
5. `"НПЗ удар дрон сентябрь 2026"`
6. `"Крым бензин дефицит 2026"`

## Ожидаемые результаты и действия
После выполнения поисковых запросов через `bash agents/websearch.sh "<запрос>"` нужно:

1. Обработать полученные JSON-результаты с полями `results[].title/url/content`
2. Извлечь свежие события за последние 72 часа (с 2026-10-03 по 2026-10-06)
3. Сформировать новые элементы для массива `history[]` в формате:
   ```json
   {
     "date": "YYYY-MM-DD",
     "type": "strike|repair|restriction|policy",
     "title": "Краткое описание события",
     "detail": "Подробные детали события нейтральным языком",
     "refinery_id": "идентификатор НПЗ из списка или пустая строка",
     "region": "Регион где произошло событие",
     "source_url": "URL источника информации",
     "confidence": "confirmed|reported|rumored"
   }
   ```
4. Добавить новые события СВЕРХУ массива `history[]`
5. Оставить не более 24 последних событий в массиве
6. Проверить наличие подтверждённого восстановления НПЗ для обновления массива `repaired[]`
7. Обновить раздел `crimea` с свежими данными о:
   - summary
   - restrictions 
   - stations (status станций: ok|limited|talon|dry)
   - routes (status маршрутов: ok|threatened|cut)
   - outlook
8. НЕ дублировать уже существующие события (проверять по дате+теме)
9. Обновить/добавить поле `generated_at` на верхнем уровне файла текущей датой (YYYY-MM-DD)
10. Сохранить валидный UTF-8 JSON и записать целиком через Write

## Требования к качеству данных
- refinery_id должен быть из списка: kinef,ryazan,moscow,perm,syzran,tuapse,kuibyshev,nnos,yanos,volgograd,omsk,taneco,ufa,achinsk,angarsk,komsomolsk,antipinsky,saratov,orsk,afipsky
- Каждое событие должно иметь ссылку-источник
- Не выдумывать информацию, использовать только подтверждённые данные из поиска
- Сохранять нейтральный русскоязычный OSINT тон
- Использовать только значения confidence: confirmed|reported|rumored
- Устанавливать confirmed только при 2+ независимых источниках/официальном подтверждении
