# Playbook: удар по складу маркетплейса

Что делать, когда приходит новость об ударе по складу Wildberries или Ozon. Порядок важен:
сначала данные, потом текст. Если сделать наоборот, статья разойдётся с цифрами на сайте.

---

## Шаг 0. Сначала данные — 10 минут, без них всё остальное соврёт

```bash
cd ~/Documents/npz-tactical-map && git fetch origin -q && git reset --hard origin/main -q
# 1) удар должен быть в ленте (обычно приезжает сам от newswatch/strike-pipeline)
python3 -c "import json;d=json.load(open('data/strikes.json'));s=d if isinstance(d,list) else d['strikes'];print([x for x in s if x.get('date','')>='СЕГОДНЯ'][:5])"
# 2) поражения выводятся из strikes.json — БЕЗ этого счётчик и рейтинг устареют
python3 agents/fetch-warehouses.py
python3 agents/gen-warehouses-page.py
```

🔴 **Самая частая ошибка проекта:** удар есть в ленте, а `fetch-warehouses.py` не прогнали.
Страница-чемпион (топ-1 по трафику) четыре дня показывала «13 складов», когда их было 16 —
всё валидно, ошибок нет, просто цифра старая. См. `npz-warehouses-sync-not-run` в памяти.

После прогона проверь, что склад появился и рейтинг обновился:

```bash
python3 -c "
import json;w=json.load(open('data/warehouses.json'))['warehouses']
print('поражённых:',sum(1 for x in w if x.get('status')=='hit'))
print('в рейтинге:',sum(1 for x in w if x.get('area_m2')))"
grep -o 'поражено [0-9]* складск' skolko-skladov-wildberries-ozon.html | head -1
```

Если у поражённого склада известна площадь — он **сам** встанет в рейтинг с пометкой
«ПОРАЖЁН», перерисовывать ничего не нужно. Если площади нет, но она находится в открытых
источниках — добавь `area_m2` + `area_source_url` (🔴 без ссылки поле не пишем) и прогони
генератор ещё раз.

## Шаг 1. Решить: новая страница или в существующую

🔴 **По умолчанию — В СУЩЕСТВУЮЩУЮ.** Кластер складов держат уже 10 страниц реестра;
одиннадцатая под тот же интент отнимет трафик у своих же, а не приведёт новый.

**В хронику `ataki-na-sklady-wildberries-hronika` (обычный случай):**
удар по региону/сети, о которых уже писали. Добавляется эпизод в том же формате, что
соседние, + обновляется дата «Обновлено».

**Новая страница — только если появился ИНТЕНТ, которого нет в реестре.** Проверить:

```bash
python3 -c "
import json
for l in open('data/seo-topics.jsonl',encoding='utf-8'):
    t=json.loads(l); kw=(t.get('primary_kw','')+' '+' '.join(t.get('keywords',[]))).lower()
    if 'склад' in kw: print(t['url'],'|',t['primary_kw'])"
grep -ril "НАЗВАНИЕ_ГОРОДА" *.html | head
```

Оправданные поводы для новой страницы (по прецедентам):
- **новая гео-привязка**, которой нет ни у одной страницы (так появилась
  `/udar-sklad-wildberries-peterburg` — интент «удар по складу wildberries спб»);
- **новый вопрос аудитории**, а не новое событие («что делать», «компенсации», «вырастут ли цены»).

Если сомневаешься — в хронику. Ошибка «не создал страницу» стоит дешевле, чем
каннибализация чемпиона.

## Шаг 2. Если делаем страницу — скелет по рабочему образцу

Образец: `udar-sklad-wildberries-peterburg.html` (26 КБ, 3 блока JSON-LD, ~115 внутренних
ссылок). Повторять его структуру, а не изобретать:

```
<title>   Удар по складу Wildberries в <МЕСТО> <ДАТА>          — ключ в начале, 50–60 знаков
<h1>      Удар по складу Wildberries в <МЕСТО>: <ДАТА>
Лид       2–3 предложения: что, где, когда, что с объектом. Без «воды» и оценок.

H2 📍 Что известно по объектам      — факты из strikes.json: адрес, тип, статус, источник
H2 🗓 Хронология ударов             — привязка к предыдущим датам (18 → 22 → 24 июля)
H2 🚚 Последствия для доставки в <ФО> — сроки, перераспределение по сети, без паники
H2 ❓ Частые вопросы                 — 4–6 вопросов реальными формулировками запросов
H2 🔗 Смотрите также                — чемпион, хроника, карта складов, компенсации
```

**Куда вставить рейтинг:** ссылкой на чемпиона в блоке «Смотрите также» — сам рейтинг живёт
там и обновляется генератором. 🔴 Не копировать сетку карточек в статью: копия застынет,
а оригинал обновляется.

**Тон:** строго нейтральный OSINT-русский. Никакого злорадства, оценок сторон и эпитетов —
на pre-commit висит `agents/censor.py`, он блокирует публикацию. Даты по-русски
(«29 июля 2026»), не ISO.

**Числа:** только из `data/*.json`. Площади — с `area_source_url`. Оценки подписывать
оценками (как «Потери выпуска · оценка» в панели баланса).

## Шаг 3. Публикация — порядок жёсткий

```bash
# работать ТОЛЬКО в отдельном worktree: фоновый git-sync ресетит общее дерево
git worktree add /tmp/wt-udar origin/main && cd /tmp/wt-udar

# 1) новая страница → СНАЧАЛА запись в реестр, иначе выпадет из меню и sitemap
#    строка в data/seo-topics.jsonl: {"url":"/...","type":"reference","primary_kw":"...","keywords":[...],"created":"...","status":"live"}
python3 agents/build-nav.py      # меню + sitemap + штамп ?v
python3 agents/check-ia.py       # падает, если страница осиротела
python3 agents/censor.py <файл>.html
python3 -c "import json,re;h=open('<файл>.html',encoding='utf-8').read();[json.loads(m) for m in re.findall(r'<script type=\"application/ld\+json\">(.*?)</script>',h,re.S)];print('JSON-LD ok')"

# 2) коммит поимённо (git add -A запрещён), UI-shell → ALLOW_FRONTEND_RELEASE=1
git add <файл>.html data/seo-topics.jsonl sitemap.xml <изменённые меню-файлы>
git commit -m "..."

# 3) пуш — цикл с повторами: заливка ~189 с, а VPS коммитит каждые 2–10 мин
for i in 1 2 3 4 5; do
  git fetch origin -q; git rebase origin/main >/dev/null 2>&1
  GH_TOKEN=$(gh auth token -u volobuevaleksand7-hue) git -c credential.helper='!f(){ echo "username=volobuevaleksand7-hue"; echo "password=$GH_TOKEN"; };f' push origin HEAD:main && break
done
```

🔴 `gh auth switch` запрещён глобально. Живая копия — `~/Documents/npz-tactical-map`,
НЕ `Alarm NPZ`.

## Заготовки текста

Подставить `<МЕСТО>`, `<ДАТА>`, `<ОБЪЕКТ>`; факты брать из `strikes.json`, не по памяти.

**Лид:** «В ночь на <ДАТА> сообщается об ударе по <ОБЪЕКТ> в <МЕСТО>. По открытым данным,
<что с объектом: пожар / остановка работы / повреждение>. Это <N>-й подтверждённый удар по
складской инфраструктуре маркетплейсов с начала <месяца/года>.»

**Вопросы FAQ** (формулировать так, как ищут):
- Какой склад Wildberries пострадал в <МЕСТО>?
- Что будет с заказами, которые лежали на складе?
- Сколько складов Wildberries уже поражено? → ссылка на чемпиона
- Вырастут ли цены и сроки доставки? → ссылка на `/ceny-marketpleysy-posle-udarov`
- Кто компенсирует продавцам утраченный товар? → ссылка на `/kompensacii-wildberries-posle-udara`

**Что НЕ писать:** прогнозы «что будет дальше», оценки действий сторон, непроверяемые суммы
ущерба, эмоциональные эпитеты. Проект держится на том, что его цифры можно перепроверить.
