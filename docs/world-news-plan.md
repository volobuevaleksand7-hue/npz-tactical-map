# Рубрика «Всемирные новости» и английская версия /en/world — план (14.10.2026)

Сведён из ответа Codex (gpt-6-sol) и собственного видения. Статус: каркас в ветке `world-news`, в main не выложен.

## 1. Формат рубрики
- Отдельные выпуски `/world/news/<YYYY-MM-DD>` и индекс `/world/news`; на `/world` остаётся карта и ИТН, плюс ссылка на рубрику. Согласие с Codex: у выпуска постоянный адрес и зафиксированный набор данных.
- Частота: по событиям, не по календарю. Не более одного выпуска в сутки, и только если после прошлого выпуска появилось одобренное событие. Пустых страниц нет. Дата в URL — дата публикации (UTC).
- В выпуск попадают только события с `review: approved`, ещё не вошедшие в прежние выпуски (по `id`). Сейчас таких 6 из 21.
- Состав: заголовок по главному событию; ИТН мира (значение, дельта, покрытие) со снимком на момент выпуска; карточки событий (статус confirmed/reported, влияние на топливо, источники); дисклеймер «ОЦЕНКА»; ссылка на методику. Нельзя писать, что событие «вызвало» изменение ИТН: события на балл не влияют.
- Снимок ИТН хранится в `data/world/news-archive.json`, старый выпуск не пересчитывается по текущему `index.json`.

## 2. Кто пишет
Генератор `agents/world/gen-news.py` — stdlib, без LLM. Лид по умолчанию собирается шаблоном из фактов. Haiku может предложить лид в `news-archive.json` (`lead_ru`/`lead_en`) по жёсткому шаблону и только из фактов выпуска. Владелец одобряет готовую страницу. Лексика проверяется тем же словарём нейтральности, что у событий.

## 3. Английская версия
- Статические страницы `/en/world`, позже `/en/world/news[/<date>]`. Один код (`world.css`, `world-app.js`), язык берётся из `<html lang>`.
- hreflang `ru`/`en` + `x-default` (на русскую) на существующих парах, canonical свой. Видимый переключатель RU/EN. Редиректа по IP и языку браузера нет.
- Перевод по глоссарию от замороженного русского текста. У событий поля `title_en`, `summary_en`, `fuel_effect_en`; разведчик пишет оба языка, валидатор предупреждает (warning) об их отсутствии.
- Расхождение с Codex: Codex предлагает скрывать из английской карты события без перевода. Выбрано иное: событие остаётся на карте, текст русский с пометкой о непереведённости. Английский выпуск рубрики, напротив, выходит только при полном переводе своего состава.
- Пояснения компонентов ИТН (`raw`) пока русские: на английской странице скрыты до появления `raw_en` в `index.py`.

## 4. SEO
Самоканонические URL, уникальные title/description по главному событию, JSON-LD `NewsArticle` для выпуска и `CollectionPage` для индекса, выпуски в `sitemap.xml` с hreflang-парами, позже `/world/rss.xml`. Без `meta keywords`.

## 5. Риски
Не публиковать `lab` и очередь; не выдавать `reported` за `confirmed`; не приписывать событию дельту ИТН; не плодить пустые выпуски; не пересчитывать старые выпуски.
