# NPZ Status — ревизия состояния и приоритеты

Репозиторий: **`~/Documents/npz-tactical-map`** (живой; вторая копия `~/Documents/Alarm NPZ`
устарела, но НПЗ-сессии штатно идут и оттуда). Сайт читает `data/*.json` с GitHub raw сразу
после пуша; статические страницы — после деплоя (workflow триггерится push'ем не-`data/**`).

Твоя роль — **ревизор и приоритизатор**: снять картину по всему проекту одним прогоном,
объяснить, что горит, и предложить порядок работ. Действуешь по приоритетам сам только если
Серёга просит; иначе — докладываешь список и ждёшь выбор.

## Шаг 0 — синхронизировать репо (ОБЯЗАТЕЛЬНО)

Скрипт считает по локальным файлам. Локальная копия часто отстаёт на сотни коммитов (весь
труд в облаке/параллельных сессиях), поэтому сначала:

```
cd ~/Documents/npz-tactical-map && git fetch origin -q && git reset --hard origin/main -q && git log --oneline -1
```

Без этого ревизия соврёт «протухло/нет сводки» на устаревших данных.

## Шаг 1 — прогнать ревизор

```
NPZ_REPO=~/Documents/npz-tactical-map python3 ~/.claude/skills/npz-status/scripts/npz-status.py
```

(`--json` — машинный вывод; `--selfcheck` — тест логики.) Скрипт печатает 4 среза:

1. **АГЕНТЫ** — `health.json`: overall, stale/dead, publish_lag, проблемные слои. 🔴 = флот
   болен, разбирать ДО контента (читать `agents/logs/<label>.log`, не только живость — см.
   память про ложную диагностику).
2. **СВОДКИ** — есть ли сегодняшняя сводка, последняя страница, последний удар, отсутствующие
   свежие обложки.
3. **SEO** — планируемые страницы (`status=planned` в реестре), **протухшие live-страницы**
   (их `dateModified` отстаёт от сегодня >10 дн — сигнал, что хардкодные цифры устарели),
   бэклог-идеи по частотности.
4. **ЧТО ПЕРВЫМ** — единый список 🔴/🟡/🟢 по уровням: сломанное → контент-долг → рост.

Прочитай вывод и доложи Серёге кратко: здоров ли флот, что со сводками, и топ-приоритеты.

## Шаг 2 — действовать по приоритетам (если просят)

**🔴 Сломанное/пропущенное операционное — первым.**
- Флот не healthy → диагностика по логам агентов; данные о ложной «живости» — в памяти.
- Нет сводки за сегодня / дырки в ударах / нет обложек → это работа парного скилла
  **`npz-map-refresh`** (догнать удары → gen-news → build-covers → publish). Не дублируй его
  логику здесь — вызови его.

**🟡 Протухшие live-страницы — контент-долг.** У страницы старый `dateModified` и хардкодные
цифры в прозе (кризис/дефицит/регионы/аналитика). Освежить:
- поднять свежие числа из `data/fuel-state.json` (баланс, % выбытия, дефицит-регионы),
  `data/strikes.json` (удары), `data/forecast.json`+`economy.json` (сценарии/макро);
- заменить ТОЧЕЧНО (не блэнкет-заменой коротких чисел — она молча портит исторические
  формулировки и даты ссылок на старые сводки; всегда проверяй diff после);
- обновить `dateModified` в ld+json И видимую строку «Обновлено N месяца 2026» —
  на реальный возраст контента, не «на сегодня» ради красоты (иначе переобещаешь свежесть);
- `data-driven` оболочки (`/npz/*`, `/karta*`, `/radar`, `/refineries`) скрипт НЕ штрафует —
  они тянут свежие цифры на клиенте, их старый `dateModified` это норма.

**🟢 Рост — планируемые статьи, затем бэклог по частотности.**
- Страницы `status=planned` в `data/seo-topics.jsonl` — писать по **механизму SEO-страниц**:
  ручная страница на скелете существующей (взять любую `reference`-страницу как каркас,
  переписать head+main), зарегистрировать в `seo-topics.jsonl` ДО публикации, `build-nav.py`
  + `check-ia.py` + `seo/generate-sitemap.py`.
- 🔴 **Анти-каннибализация:** перед новой статьёй прогони `seo-topics.jsonl` на пересечение
  интента — в проекте уже были коллизии (`/deficit` vs `/crisis`, три страницы про склады ВБ
  от параллельных сессий). Общий интент дефер на существующую страницу явной ссылкой.
- 🔴 **Нейтральность:** строго нейтральный OSINT-тон, без пропаганды/эпитетов/оценок —
  `agents/sanitize-strikes.py` и цензор в pre-commit режут нарушения, и это держит проект
  как источник, а не агитку. Каждая цифра — из `data/*.json`, не из головы; прогноз помечать
  прогнозом, отсутствие данных — отсутствием.

## Шаг 3 — опубликовать

- **Данные** (`data/*.json`): `bash agents/git-sync.sh "<msg>"` — безопасный синк флота
  (коммитит только `data/`, ловит conflict-маркеры, heartbeats).
- **Статика** (страницы, обложки, sitemap): собрать в один коммит и запушить. `build-nav.py`
  трогает `index.html`/`radar.html` под релизным гейтом — если правка чисто навигационная
  (ссылки в меню), это осознанный `ALLOW_FRONTEND_RELEASE=1` коммит; если нет — выведи их из
  коммита (`git restore --staged index.html radar.html`).
- **Пуш** — анонимным аккаунтом, точечным токеном (правило `git-account-hygiene`):
  ```
  cd ~/Documents/npz-tactical-map && git pull --rebase origin main && GH_TOKEN=$(gh auth token -u volobuevaleksand7-hue) git -c credential.helper= -c credential.helper='!gh auth git-credential' push origin main
  ```
  Дерево перед `pull --rebase` должно быть чистым (флот запрещает autostash). Origin пушится
  каждые ~10 мин — гонки нормальны, ребейзься и пушь снова. Хук `git-account-guard` разрешает
  анон-аккаунт только из НПЗ-каталогов.
- Проверь деплой (`gh run list ... "Deploy to Vercel (production)"`) и живой URL.

## Заметки

- Параллельные сессии в репо — норма; они уже дважды дублировали бэклог. Перед крупной
  работой глянь свежие коммиты origin и `AGENT_ACTIVITY.md`, чтобы не писать то же самое.
- Порог протухания (10 дн) и списки evergreen/data-driven — в шапке скрипта, правь под фокус.
- Позиции Яндекса/Google пишет VPS-рутина в `data/yandex-positions.json` (локально может
  отсутствовать); список ключей — `data/position-queries.json`. Если файл позиций есть —
  используй его как дополнительный сигнал приоритета (поз. 4-10 → топ-3 = рычаг роста).
