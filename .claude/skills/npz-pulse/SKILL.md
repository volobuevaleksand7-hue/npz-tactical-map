# NPZ Pulse — расклад дел и предложения роста

Репозиторий: **`~/Documents/npz-tactical-map`** (живой; `~/Documents/Alarm NPZ` — устаревшая
копия, но сессии штатно идут и оттуда). Прод: npz-tactical-map.vercel.app.

Твоя роль — **аналитик роста**, а не диагност. `npz-status` отвечает на вопрос «что сломано»,
этот скилл — на вопрос «где деньги и внимание, и что делать дальше». Финал работы всегда один:
**расклад цифрами + 3–5 конкретных предложений с обоснованием**. Не начинай ничего писать и
деплоить, пока Серёга не выберет — если он прямо не сказал «делай».

## Шаг 0 — синхронизировать репо (ОБЯЗАТЕЛЬНО)

```
cd ~/Documents/npz-tactical-map && git fetch origin -q && git reset --hard origin/main -q && git log --oneline -1
```

Локальная копия хронически отстаёт: работает флот агентов и параллельные сессии, data-коммиты
идут каждые ~10 минут. Без синка анализ соврёт на устаревших файлах.

## Шаг 1 — собрать факты

```
python3 ~/.claude/skills/npz-pulse/scripts/pulse.py
```

(`--json` — машинный вывод, `--days N` — окно, `--selfcheck` — тест логики.)

Скрипт ходит за токенами на `hermes-vps` и собирает шесть блоков: здоровье флота, трафик за
14 дней, топ страниц с трендом, SEO-приток новых фраз, свежие удары против наличия страниц,
монетизация. Он НИЧЕГО не советует — только факты.

🔴 Если блок помечен «данные недоступны» — так и скажи Серёге. Не заполняй дыру догадкой и не
выдавай прошлые цифры за свежие.

## Шаг 2 — анализ, строго в этом порядке

Порядок не случайный: он идёт от того, что уже работает, к тому, чего ещё нет. Дешёвое —
раньше дорогого.

### 2.1. Что уже идёт лучше всего — это усиливать первым

Смотри топ страниц за вчера и их тренд. Растущая страница с трафиком — самая дешёвая точка
роста: она уже доказала спрос, ей нужен не запуск с нуля, а докрутка. Отвечай на вопросы:
какая страница выросла и почему (новостной повод? сезон? наш реопт?), держится ли рост
второй день, есть ли у неё потолок по позициям.

🔴 Не путай всплеск с трендом. Один день выброса на новостном поводе — не рост, а волна: она
сдуется за 2–4 дня. Проверяй по ряду дней, а не по «вчера против позавчера».

### 2.2. SEO-приток — что нового к нам пришло

Блок 4 даёт новые фразы и фразы с ростом показов. Это самый честный индикатор того, куда
двигается спрос, и он опережает трафик: сначала растут показы, потом клики.

Разбирай приток на три корзины:
- **есть страница, ранжируется** → кандидат на реопт (усилить то, что уже есть);
- **есть страница, но не по этой фразе** → кандидат на доработку текста/FAQ;
- **страницы нет вовсе** → кандидат на новую статью.

Туда же — список almost-there (позиции 4–10): страницы у порога топ-3, самый дешёвый рост
в кликах. 🔴 Но сначала проверь, не был ли реопт уже сделан: `git log --follow <файл>` и
заметки в `data/seo-topics.jsonl`. Правило проекта — **не наслаивать реопт на реопт до замера**,
окно замера 7–10 дней. Если недавно правили — предлагай не правку, а дату замера.

### 2.3. Новостные поводы — что горит прямо сейчас

Блок 5 сопоставляет свежие удары с реестром страниц. Здесь скорость решает больше, чем
качество: тема живёт 2–4 дня, страница, вышедшая на третий день волны, собирает остатки.

🔴 Жёсткое правило проекта: **новые удары по уже покрытой теме идут в СУЩЕСТВУЮЩУЮ
reference-страницу, а не новой страницей.** Мы на этом уже обжигались. Новая страница
оправдана только под новый интент, которого в реестре нет.

### 2.4. Монетизация и техника

Клики по VPN, воронка подписки, состояние квоты Vercel. Здесь редко бывает срочное, но если
конверсия обвалилась — сначала выясни, не наша ли это правка текста/размещения, и только
потом ищи поломку. 🔴 Клики ≠ продажи: у прошлой партнёрки было 300 кликов и ноль продаж.

## Шаг 3 — сверка предложений с реестром (🔴 обязательный фильтр)

Прежде чем предложить ЛЮБУЮ новую страницу — проверь три источника, иначе предложишь то, что
уже сделано или заведомо вредно:

1. `data/seo-topics.jsonl` — там у каждой живой страницы закреплены ключи и **явно прописаны
   границы интентов между страницами**. Если ключ уже закреплён — новая страница будет
   самоканнибализацией, а не ростом. Именно так однажды чуть не выпустили дубль под кластер,
   который уже держала живая страница.
2. `data/seo-backlog.jsonl` — идеи со статусами. `status=done` с заметкой «закрыто, потому
   что…» означает, что вопрос уже разбирали. Не воскрешай.
3. `docs/seo-playbook.md` — правила против каннибализации.

Ревизор `npz-status` показывает бэклог-идеи как приоритеты, **но он не знает, что часть из них
уже закрыта реоптами живых страниц**. Реестр важнее ревизора.

## Шаг 4 — выдать расклад

Формат ответа Серёге — коротко и цифрами, без воды:

1. **Состояние** — 2–3 строки: флот, трафик (вчера против недели), что сломано.
2. **Что растёт** — 3–5 строк с цифрами и причиной роста.
3. **Приток спроса** — новые и растущие фразы, с пометкой, есть ли под них страница.
4. **Предложения: 3–5 пунктов**, каждый в одну-две строки по схеме
   *что сделать → на каких цифрах основано → сколько это стоит по усилиям*.
   Смешивай типы: не только статьи, но и реопты, техфиксы, доработки функционала. Обязательно
   ранжируй по отношению «эффект / усилия», а не по объёму частотности.
5. **Что НЕ делать** — если по цифрам видно, что популярная идея бессмысленна, скажи об этом.
   Это ценнее пятого предложения.

Затем жди выбора. Если Серёга говорит «делай» — раздавай субагентам (правила ниже).

## Правила исполнения, если дошло до работы

- Субагенты: контент и код — **Sonnet**, мелкая механика и диагностика — Haiku, Opus только
  на действительно тяжёлое. Каждому — свой git worktree от `origin/main`, работа в общем
  дереве запрещена (там чужие незакоммиченные правки флота).
- Push только точечным токеном: `GH_TOKEN=$(gh auth token -u volobuevaleksand7-hue) git push
  origin HEAD:main`. 🔴 `gh auth switch` запрещён глобально. Перед push — `git fetch origin main
  && git rebase FETCH_HEAD`, origin уходит вперёд каждые ~10 минут.
- `git add -u/-A` запрещён — файлы поимённо. Фронтенд-коммит с префиксом
  `ALLOW_FRONTEND_RELEASE=1`.
- Push в main сам запускает CI-деплой; локально `vercel` не запускать. Дождаться зелёного
  прогона и проверить прод живьём.
- Новая страница требует записи в реестре публикатора ДО публикации, иначе выпадет из
  навигации и sitemap. После — `python3 agents/build-nav.py` (он же штампует `?v=`).
- 🔴 Тон строго нейтральный OSINT-русский, в pre-commit висит цензор. ПВО на картах не
  отмечать никогда. Даты в UI по-русски. Атрибуция Leaflet без флагов.

## Чему верить, а чему нет

- **Отчётам субагентов не верить на слово.** Проверяй ключевые числа сам по исходным данным:
  агент может уверенно отчитаться о том, чего не делал, или посчитать не то. Это уже ловили.
- **Ревизору верить в диагностике, не верить в приоритетах** — см. шаг 3.
- **Абсолютным цифрам за неполный день не верить.** Сравнивай только равные окна: 00:00–14:00
  против 00:00–14:00, иначе получишь «падение в 20 раз» там, где просто день не кончился.
- **Мелкая выборка ничего не доказывает.** 4 клика против 5 — это шум. Если для вывода не
  хватает данных, честно скажи, сколько дней надо копить, и не выдумывай вывод.
