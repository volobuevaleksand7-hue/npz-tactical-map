# NPZ Map Refresh — ручное обновление карты

Репозиторий карты: **`~/Documents/npz-tactical-map`** (все пути ниже — относительно него).
Сайт читает `data/*.json` напрямую с GitHub raw — как только коммит ушёл в `origin/main`,
карта обновляется без редеплоя. Никакого VPS/крона нет; облачные Anthropic-рутины сейчас
на паузе, поэтому обновляем **вручную этим скиллом**.

Твоя роль здесь — **оркестратор**: ты не собираешь данные сам (это дорого), а раздаёшь
слои внешним агентам, проверяешь их работу и делаешь один безопасный пуш. Собирать самому
(Claude-субагентом) — только фолбэк, когда внешний агент сфейлил или вернул подозрительное.

## Железные правила (нарушение = порча карты или дезинформация)

1. **НИКОГДА не выдумывать.** Каждый факт (удар, лимит АЗС, цитата, цифра) — с реальным
   `source_url`, который агент действительно получил. Нет подтверждения → запись не добавляется.
   Это боевые данные о войне; фейк здесь хуже, чем пропуск. (Ровно за фейки-«Math.sin» в
   чёрном списке конкурент gdebenzin.)
2. **Агенты пишут ТОЛЬКО свой `data/*.json`.** Они НЕ трогают `data/heartbeats.json` и
   НЕ запускают git (add/commit/pull/push). Heartbeats и единый пуш делает оркестратор —
   иначе параллельные пуши конфликтуют (autostash-коллизия на last-sync.txt, из-за которой
   в июне вставал весь флот).
3. **Один пуш в конце** через `scripts/publish.sh` — он валидирует JSON, ловит
   conflict-маркеры и вызывает `agents/git-sync.sh` с нужными heartbeat-ключами.
4. **Проверяй каждый результат агента** перед пушем (см. шаг 4). Внешние агенты флакают и
   иногда галлюцинируют — доверяй, но верифицируй `source_url` и даты.

**Приоритет — удары.** Серёга особо просит не пропускать удары: strikes собирай всегда,
ищи ВСЕ пропущенные даты между последней записью и сегодня, а не только «за сутки».
**АЗС всегда гнать на сегодняшнюю дату** (`meta.generated_at` = сегодня), даже если новостей
мало — обновить хотя бы приоритетные регионы трассы М4 и биржу СПбМТСБ.

## Инструментарий делегирования (у кого какие возможности)

Внешние агенты НЕ имеют серверного WebSearch Anthropic — но есть **Tavily** (`scripts/tavily.sh`,
ключ уже настроен в `~/.tavily/api_key`), search-API специально под LLM-агентов: чистый JSON по
curl, без CAPTCHA (в отличие от DuckDuckGo-html). Это теперь ОСНОВНОЙ поисковый путь для
DeepSeek/MiMo — они умеют curl/bash, просто зови `bash <skill_dir>/scripts/tavily.sh "<query>" [N] [days]`
из промпта агента (пример вызова и параметры — см. коммент в самом скрипте). `days` включает
режим свежих новостей (topic=news) — используй его для strikes/АЗС/электросетей.

- **DeepSeek (расширенный)** — `bash scripts/deepseek-web.sh "<промпт>"` — снимает read-only-
  ограничение штатного лаунчера и даёт Bash+WebFetch+Tavily. В промпте агенту явно пропиши:
  «ищи через `bash <абсолютный_путь>/tavily.sh "<query>" 6 3`» (передай агенту абсолютный путь
  к `tavily.sh`, т.к. его cwd — repo карты, не skill dir). Плюс Telegram-зеркала как второй канал:
  `curl -s -A "Mozilla/5.0" https://t.me/s/<channel>` (nefte_baza, oil_capital — цены/лимиты;
  Crimeanwind, chp_krd, RndCHP — регионы; astrapress — сводки). **Проверено рабочим.**
- **MiMo** — Agent tool `subagent_type: mimo`. Cutoff начало 2025, но есть Bash → тоже может
  звать `tavily.sh` напрямую (пропиши путь и синтаксис вызова в промпте). Плюс годится для
  **механических скриптов** (`python3 agents/strike-confirm.py`, `python3 agents/healthcheck.py`).
  Медленнее DeepSeek — не первый выбор для research-слоёв, но с Tavily должен справляться.
- **Gemini CLI** — Google-grounded поиск, хорош для ударов, но: `gemini -m gemini-3-pro-preview -p "<промпт>"`
  (в repo). Как **researcher**: пусть ВЕРНЁТ события JSON-массивом с URL (без правки файла).
  ⚠️ Бесплатная квота часто исчерпана (HTTP 429 `TerminalQuotaError`) — тогда сразу пробуй
  DeepSeek+Tavily или фолбэк на Claude, не зависай на ретраях.
- **Claude-субагент** — Agent tool `subagent_type: general-purpose` — есть родные WebSearch/
  WebFetch, самый надёжный, но самый дорогой по контексту оркестратора. **Фолбэк**: если
  DeepSeek/MiMo/Gemini вернули пусто/подозрительное, особенно по ударам — переотправь слой сюда.

**Порядок предпочтения по умолчанию:** DeepSeek+Tavily (быстро, дёшево, надёжно) → Gemini (если
квота жива) → MiMo (для тяжёлых research-слоёв — только если оба выше недоступны) → Claude-
субагент (фолбэк/верификация приоритетных слоёв вроде strikes).

Запускай writer-агентов ПАРАЛЛЕЛЬНО (разные файлы — конфликта нет). В промпте КАЖДОМУ агенту
вставляй три «железных правила» (не выдумывать; писать только свой файл; git/heartbeats не
трогать) и путь к его спеке `agents/update-prompt-*.md` (пусть прочитает её сам).

## Рабочий процесс

**Шаг 1 — оценить пробелы.** `bash scripts/assess.sh` — покажет по каждому слою
`generated_at`, возраст, STALE. Отметь, что отстало и какие даты пропущены (для strikes —
диапазон от последней записи до сегодня).

**Шаг 2 — распределить и запустить (параллельно).** Дефолтный расклад (адаптируй под пробелы):
- **strikes** (критично) → **Gemini** (свежесть) ИЛИ Claude-субагент; ищи ВСЕ пропущенные даты.
- **fuel-availability (АЗС на сегодня)** → DeepSeek-web ИЛИ Gemini.
- **fuel-voices** → DeepSeek-web (проверенный путь через t.me-зеркала).
- **fuel-state / history / roads / grid** → Gemini или DeepSeek-web, по одному агенту на слой
  (или объединить fuel-state+history+roads в одного «NPZ»-агента по трём спекам).
- **forecast+economy+capacity-timeline** → Gemini или DeepSeek-web (аналитика поверх fuel-state).
- **strike-confirm.py + healthcheck.py** → MiMo (или просто запусти сам: это детерминир. скрипты).

Не обязательно каждый раз обновлять всё — покрывай то, что STALE + strikes + АЗС всегда.

**Шаг 3 — дождаться агентов.** Они пишут свои файлы в рабочем дереве.

**Шаг 4 — верифицировать (критично, анти-фейк).** По каждому изменённому файлу:
`git diff --stat data/` и выборочно проверь новые записи — есть ли реальный `source_url`,
правдоподобны ли даты (в окне, не из будущего/далёкого прошлого), не выдуманы ли города/цифры.
Если агент вернул «пусто» по слою, где новости точно были (особенно strikes), или запись без
URL — **переотправь этот слой Claude-субагенту** и замени файл его версией. Лучше меньше, но
настоящих записей.

**Шаг 5 — опубликовать.** `bash scripts/publish.sh "<сообщение>"` — валидирует все изменённые
JSON, ловит conflict-маркеры, вычисляет heartbeat-ключи по изменённым файлам и делает один
`git-sync.sh` push. Успех = строка `git-sync: pushed -> live via GitHub raw`.

**Шаг 6 — отчёт.** Кратко: какие слои обновил, ключевые новые события (удары по городам, лимиты
АЗС, биржа), какие даты догнал, кто из агентов что собрал, что осталось/не подтвердилось.
Напомни про жёсткий refresh (Cmd/Ctrl+Shift+R).

## Новостной раздел /news (сайт) + обложки + Telegram

Помимо data-слоёв карты у проекта есть **новостной сайт-архив** и **Telegram-канал @NPZmap**.
`publish.sh` уже делает две пост-обработки автоматически после пуша данных:
- **`agents/gen-news.py`** — генерит новостной раздел из свежих данных:
  - `news.html` — ИНДЕКС `/news`: герой (свежая сводка + обложка) + нац.баланс + лента карточек по всем датам.
  - `news/<YYYY-MM-DD>.html` — отдельная страница-сводка за каждый день (удары+голоса+prev/next), для свежей даты — ещё баланс/АЗС/биржа.
  - `data/news-archive.json` — НАКОПИТЕЛЬНЫЙ архив: даты не теряются, когда rolling-window `strikes.json` подрезается.
  - `sitemap.xml` (все даты) + cache-busting `?v=<хэш>` на css (иначе браузер держит устаревший CSS → «вырви глаз»).
- **`bot/broadcast.py`** — шлёт дайджест в канал @NPZmap и в личку подписчикам, **с картинкой-обложкой дня** (берёт `assets/cover-<дата>.png`, ту же, что на сайте; фолбэк — авто-карточка render_card).

⚠️ **Сайт (`news.html`, `index.html`) live только после `vercel --prod`** — data-слои live сразу через
GitHub raw, а статические страницы сайта требуют деплой. После обновления новостей делай `cd repo && vercel --prod`.

### Обложки сводок (`scripts/build-covers.py`)

Одна обложка = одна дата, **едина для сайта и Telegram**. Стиль (правило Серёги, [[npz-cover-image-style]]):
**НЕ мрачно; конкретный город удара + подпись на картинке «Город — что произошло».**

Пайплайн (в `build-covers.py`): для каждой даты берётся ЛИД-удар из `news-archive.json` →
1. **парсим реальное фото** события: `og:image` из `source_url` статьи-первоисточника (+гейт качества: ≥600px, ландшафт, не лого) — реальный кадр;
2. **генерим по нему** обложку через `codex exec image_gen` в **img2img**-режиме (референс = реальное фото; композиция/объект сохраняются, но это новая AI-иллюстрация → без republish-копирайта и без «фото выдаём за факт»). Нет годного референса → чистая генерация по тексту;
3. **вшиваем подпись** через `agents/caption_cover.py` (Pillow, Arial Bold — кириллица, брендовая подложка) → `assets/cover-<date>.png`.

Запуск: `python3 scripts/build-covers.py --missing` (только даты без обложки) / `--all` / `--dates 2026-07-05,...`.
После — `python3 agents/gen-news.py` подхватит новые обложки, затем publish + `vercel --prod`.

🔴 **Бэкенд картинок = image-кредиты Codex.** `image_gen` рисует ~14 картинок и упирается в
«workspace out of credits». Тогда часть дат остаётся на общей заглушке `og-image.png` — это не
поломка. Пополнить кредиты и до-гнать `--missing`, либо поднять альтернативный бэкенд (Gemini image /
`GEMINI_API_KEY`). Codex-сабагент `codex:codex-rescue` для картинок КАПРИЗНИЧАЕТ (часто отказывается) —
зови `codex exec` напрямую, как в `build-covers.py`.
