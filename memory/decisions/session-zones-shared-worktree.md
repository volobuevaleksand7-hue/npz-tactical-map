# Зоны сессий в общем рабочем дереве

## Решение

Несколько агентов/сессий работают в ОДНОМ рабочем дереве (`~/Documents/npz-tactical-map` на Маке). Сессия может объявить зону — создать `.claude/zones/<имя>.zone` со списком glob-путей, по которым она работает. `.githooks/pre-commit` **предупреждает** (не жёстко блокирует навсегда — обходится `ALLOW_CROSS_ZONE=1`), если в коммит попал файл из чужой свежей зоны. Своя зона объявляется переменной `NPZ_ZONE` (можно несколько через пробел).

## Почему

01.08.2026: параллельная сессия сделала `git add -A` и утащила в свой коммит незакоммиченную правку соседней сессии — фикс геокодера складов уехал под чужим сообщением, смысл в истории потерялся (пришлось восстанавливать задним числом в `docs/agents/warehouses-geocode-fix-2026-08-01.md`). В тот же день `git-sync` дважды снёс чужую незакоммиченную работу другим путём. Корень один: сессии не знают друг о друге.

## Две конкретные ловушки при реализации (обе уже наступили)

1. **GNU vs BSD `stat`.** Возраст зоны сначала брался через `stat -f %m` (BSD-форма) как фолбэк. На VPS (Linux, GNU stat) это НЕ ошибка синтаксиса — интерпретируется как другая команда, печатает `File: ...` вместо числа. Арифметика (`now - zmod`) падала под `set -u` («unbound variable»), обваливая **каждый** коммит на VPS. Фикс: `git log -1 --format=%ct` первым, `stat -c %Y` / `stat -f %m` — фолбэк только для не-git случаев.
2. **mtime лжёт про возраст в свежем worktree.** `git worktree add` штампует ВСЕ файлы временем чекаута — трёхдневная зона выглядит рождённой минуту назад. А субагентам ПРЕДПИСАНО работать именно из worktree (см. `memory/facts/shared-worktree-git-hygiene.md`) — то есть guard по mtime блокировал бы КАЖДЫЙ их коммит навсегда (05.08.2026: зоны от 02.08, возрастом ~70ч, считались живыми). Возраст зоны берётся из `git log`, mtime — только фолбэк.

## Что я сломаю, если не буду это знать

- Скопирую подобный TTL-механизм в другой проект, взяв mtime за основу — он сломается ровно тем же способом при первом же worktree.
- Увижу «BLOCKED — файлы из чужой активной зоны» и решу, что это жёсткий запрет — на деле это предупреждение о пересечении, обходится `ALLOW_CROSS_ZONE=1`, если правка реально общая.
- Не объявлю свою зону при долгой многофайловой работе рядом с другими активными сессиями — потеряю единственный механизм, который хоть как-то предупреждает о столкновении.
