# Блокировать или чинить-и-пропускать — критерий

## Решение

`.githooks/pre-commit` несёт минимум 7 гвардов (censor, cover-weight, national-balance, archive-shrink×2, coverage, sanitize-strikes, future-dates), и они делятся на два поведения по одному критерию:

- **Блокирует (`exit 1`)**, когда правильное значение **нельзя восстановить автоматически, а гадать = подделать данные.** Пример: `future-dates` — если модель записала удар «в будущем», исправить дату можно только человеческим знанием реального времени события; авто-угадывание было бы фальсификацией. Пример: `strikes.json` shrink-guard — единственный полный архив, восстанавливать неоткуда.
- **Чинит и перезакладывает файл в тот же коммит**, когда есть детерминированный источник правды для отката/пересчёта, и публикация идёт по высокочастотному конвейеру (радар каждые 5-10 минут, множество разных рутин пишут один файл) — блокировка заклинила бы публикацию всему флоту ради одной правки. Примеры: `fuel-voices.json` (восстановление из `HEAD`), `fuel-availability.json` покрытие регионов (доклейка пропавших из `HEAD`), `national_balance` (пересчёт из `refineries[]`), обложки (пережатие на месте), `sanitize-strikes` (нейтрализация текста).

## Почему это не очевидный выбор по умолчанию

30.07.2026: флот стоял 13 часов из-за застрявшего `rebase` на `data/fuel-availability.json` — но конфликт оказался **защитным**: он не пускал урезанную версию (24 региона вместо 86) поверх восстановленных данных. `exit 1` в гварде на этом месте воспроизвёл бы ровно ту же аварию другим путём. Поэтому для `fuel-availability` и `fuel-voices` выбрана доклейка-без-блокировки — но с диагностикой **корня**, почему покрытие вообще падает (см. `memory/facts/regenerator-drops-manual-fields.md`).

Все гварды, которые ЧТО-ТО читают перед сравнением (число записей до/после), обязаны **падать закрыто**: осечка чтения = блокирующая ошибка, не молчаливый пропуск. 04.08.2026 гвард на `strikes.json` пропустил обрушение 320→0, потому что ошибка чтения давала `old_n=0`, и условие усыхания формально не срабатывало.

## Что я сломаю, если не буду это знать

- Добавлю новый гвард с `exit 1` для файла, который пишут 5 разных высокочастотных рутин — рискую повторить 13-часовой простой флота при первом же ложном срабатывании.
- Добавлю авто-починку для файла, где правильное значение принципиально неизвестно (даты, факты) — рискую тихо протащить подделанные данные на прод.
- Напишу гвард сравнения «до/после» без явной обработки ошибки чтения — он молча пропустит именно ту аварию, для которой создавался.
