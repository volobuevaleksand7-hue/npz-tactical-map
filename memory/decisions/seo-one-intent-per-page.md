# SEO: один интент — одна страница, реестр — источник правды

## Решение

Канон: **одна страница = один поисковый интент**. Перед созданием новой страницы обязателен `docs/seo-playbook.md` §0: открыть `data/seo-topics.jsonl` и проверить пересечение ключей. Если ≥40% целевых ключей уже покрыты существующей страницей — не создавать новую, дополнить существующую. Реестр знает 5 непересекающихся типов (`region|object|explainer|forecast|reference`), каждый маппится на свою группу меню.

Меню «Аналитика» на всех статьях/лендингах **генерируется** скриптом `agents/build-nav.py` из реестра — `<nav class="news-nav">` руками не редактируется, будет перезатёрто.

## Почему

Проверка «по памяти» ненадёжна: 16.07.2026 W29-отчёт аналитика едва не завёл новую страницу под «карта беспилотников», хотя интент уже держит `/karta-bpla` — спасло только сверение с `data/seo-topics.jsonl`. Дважды за один день (по независимым наблюдениям в `AGENT_ACTIVITY.md`) агент предлагал дубль страницы, потому что реестр не видит FAQ, спрятанный ВНУТРИ чужой уже живой страницы — чистого грепа реестра недостаточно.

## Практический протокол (обкатан на нескольких страницах кластера складов WB)

Проверка на дубль — **в три уровня**, не один:
1. Реестр `data/seo-topics.jsonl` (пересечение ключей).
2. Бэклог/план (не запланирована ли та же тема кем-то ещё).
3. **Грeп FAQ живых HTML-страниц** — интент может быть закрыт секцией внутри чужой страницы, которую реестр не видит вообще.

## Что я сломаю, если не буду это знать

- Заведу новую страницу под уже занятый интент → Google начнёт метаться между двумя страницами, обе просядут (каннибализация подтверждена документально для `/deficit` vs `/crisis` в `docs/seo-playbook.md` §4).
- Отредактирую `<nav>` в HTML руками — правка будет молча стёрта следующим прогоном `build-nav.py`.
- Добавлю страницу без строки в `data/seo-topics.jsonl` — пункт меню не появится нигде, `check-ia.py` завалит проверку.
- Не впишу подпись в словарь `LABELS` внутри `build-nav.py` — пункт меню напечатается сырым SEO-ключом с заглушкой 📄 (реальный случай: «сгорел склад wildberries что делать» вместо человеческой подписи).

## Смежное

Внутри кластера (например, склады WB) новый удар/новость чаще должен идти БЛОКОМ в существующую страницу-чемпион, а не отдельной статьёй — реальный прецедент: рейтинг складов по площади сделан не растровой картинкой, а генерируемой секцией внутри уже ранжирующегося чемпиона `/skolko-skladov-wildberries-ozon`, именно чтобы не каннибализировать собственный трафик.
