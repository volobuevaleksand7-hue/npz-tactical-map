# Архивные датасеты — только дописывать, никогда не перезаписывать

## Решение

`data/strikes.json` — **полный архив с 06.06.2026**, не «окно за N дней». Витрины сами фильтруют под себя (радар — 48ч, главная — пресеты). Коллектор читает существующий файл, дописывает новые записи (дедуп по `id`), никогда не удаляет старые. Аналогично `data/fuel-voices.json` — накопительный архив цитат, но там `seen` истекает по TTL (см. ниже — это не «архив», это скользящее окно, и правило для него другое).

## Почему (правило введено после ДВУХ регрессий, 2026-07-09)

- Июнь: коллектор отсёк записи старше окна → 168→110, удары мая (включая Чебоксары) утекли.
- 08.07 23:20Z: коллектор перезаписал файл свежим снапшотом целиком → 147→0→5. Восстановлено вручную.

## Страховка — но НЕ везде одинаковая

`.githooks/pre-commit` содержит **два разных по силе** гварда усыхания:

- **`strikes.json` — БЛОКИРУЕТ** коммит при падении числа записей >10% (`ALLOW_STRIKES_SHRINK=1` для обхода). Обоснование: удар по данным этого файла = удар по единственному полному архиву, восстановить нечем.
- **`fuel-voices.json` — НЕ блокирует, а восстанавливает** архив из `HEAD` и перезакладывает файл в тот же коммит. Обоснование: коммиты по этому файлу делают разные рутины, а `radar` тикает каждые 5 минут — блокировка заклинила бы публикацию всего флота ради файла, который не критичен так же, как `strikes.json`.

Оба гварда обязаны **падать закрыто**: если прочитать файл (HEAD или индекс) не удалось, это блокирующая ошибка, а не молчаливый пропуск. 04.08.2026 архив уехал в прод 320→0 именно потому, что осечка чтения давала `old_n=0`, условие усыхания не срабатывало, и страж пропускал коммит.

## Что я сломаю, если не буду это знать

- Напишу коллектор, который перезаписывает `strikes.json` снапшотом — коммит заблокируется, и придётся разбираться, почему.
- Решу, что раз `fuel-voices.json` не блокируется, можно писать в него как в окно последних N записей — сломаю семантику накопительного архива для остальных потребителей.
- Добавлю новый архивный файл без гварда — он не защищён вообще, и любая чужая рутина с `git add data/` может его обнулить (см. `memory/facts/regenerator-drops-manual-fields.md`, класс той же природы).

## Смежное

Даже сам санитайзер (`agents/sanitize-strikes.py`) один раз стал обнулителем: 14.08.2026 коллектор оставил в дереве записи без `date/city/confidence`, санитайзер честно признал их браком и удалил все 402 — но это прошло мимо гварда усыхания, потому что тот сравнивает индекс с `HEAD` **до** санитайзера, а не после. Правило для мутаторов, которые правят уже провалидированный индекс: **мутатор обязан проверять сам себя** (в pre-commit это отдельная проверка `_n0`/`_n1` вокруг вызова санитайзера).

`fuel-voices.json` также один раз попал в путаницу гвардов другой природы — если он «усох» по сравнению с историческим максимумом за счёт TTL-истекших цитат, это не баг: см. `memory/facts/fleet-health-false-signals.md`.
