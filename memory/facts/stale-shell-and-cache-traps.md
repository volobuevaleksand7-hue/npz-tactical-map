# Кэш Vercel + service worker — три разных способа показать старьё

## Что сломается, если не знать

Пользователь (или сам агент, проверяющий прод) увидит старую оболочку/старые данные и решит, что правка не задеплоилась, хотя деплой прошёл успешно — источник проблемы не в CI, а в кэшировании.

## Механизм 1 — `sw.js` попадал под общее правило кэша статики

`vercel.json` матчил `sw.js` под `/(.*).(css|js)` → `max-age=3600`. Vercel edge отдавал старый `sw.js` (`x-vercel-cache:HIT`), браузер не видел новый service worker, тот продолжал отдавать закешированную оболочку из старой версии. Фикс: `sw.js`/`version.json`/`manifest.webmanifest` получили явное правило `max-age=0, must-revalidate`, идущее ПОСЛЕ общего `.js`-правила (порядок правил в `vercel.json` важен — последнее совпадение выигрывает).

## Механизм 2 — правка CSS/JS без бампа `CACHE` в самом `sw.js`

Service worker кэширует статику cache-first под именем вида `npz-shell-v3`. Если `styles.css`/`app.js` поменялись, а версия кэша в `sw.js` — нет, новый SW не переустанавливается, и CSS/JS не обновляются у уже установивших PWA пользователей. Правило: любая правка статики оболочки требует бампа `CACHE vN→vN+1` в `sw.js` в том же коммите.

## Механизм 3 — Vercel не пуржит уже закэшированную статику деплоем; `?v` бустит не всегда

Долго-кэшируемая статика (например, `russia-regions.geojson`) не сбрасывается редеплоем сама по себе. Для файлов, НА КОТОРЫЕ ссылаются другие статические файлы (не HTML, который сам не кэшируется долго), query-параметр `?v=` не помогает — нужно **переименовать сам файл** (`russia-regions-v2.geojson`). Для ассетов, на которые ссылается HTML (`app.js?v=<hash>`, `styles.css?v=<hash>`), штамповка версии в query РАБОТАЕТ, потому что перечитывается сам HTML. `build-nav.py::stamp_assets()` автоматически проставляет `?v=<md5[:8]>` на `styles.css`/`app.js` во всех HTML при регенерации меню — но нашла и латентный баг: `index.html` линковал ассеты БЕЗ `?v`, пока лендинги — с ним, то есть у оболочки был отдельный путь без версионирования.

## Правило

- Правка `styles.css`/`app.js` → бамп `CACHE` в `sw.js` в том же коммите.
- Новая/изменённая тяжёлая статика, на которую ссылаются другие некэшируемые-редко файлы (не HTML) → менять ИМЯ файла, не полагаться на `?v`.
- После деплоя проверять живыми заголовками (`x-vercel-cache`), а не полагаться на `Cache-Control` из `vercel.json` — тот может быть переопределён заголовками самой serverless-функции (см. отдельный прецедент с `/api/radar-state`, где ветвление кэша в коде оказалось мёртвым, потому что `vercel.json` глушил его сверху).
