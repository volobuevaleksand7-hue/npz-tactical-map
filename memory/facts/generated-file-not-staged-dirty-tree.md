# Генератор пишет файл — коммит про него не знает

## Что сломается, если не знать

Публикация всего флота встанет: следующий `git-sync`/`git pull` упрётся в untracked/несведённый файл, а диагностика на первый взгляд выглядит как «сайт работает, но данные устарели» — не как «дерево грязное».

## Рецидивы (репозиторий подтверждает минимум 4 независимых случая)

1. **Обложки WebP не коммитятся.** Генератор кладёт `cover-*.png` И `cover-*.webp`, но публикующий скрипт исторически брал `git add` только по `cover-*.png` — HTML-страницы ссылаются на `.webp`, он 404. Гвард обложек в pre-commit (`cover-weight guard`) сейчас автоматически докладывает `thumb/*.webp` в `git add` при коммите `cover-*.png`, но это лечит только один частный путь — новый генератор обязан коммитить оба формата сам.
2. **`publish-stuck-dirty-tree` (ранний инцидент).** Генерируемые `sitemap.xml`/`rss.xml`/страницы кластера не попадали в `git add` пайплайна публикации — все последующие `pull` блокировались несведёнными файлами на 6+ часов.
3. **`azs-pages.py` перевыпуск сносит побочные артефакты.** Регенерация страниц из шаблона стирала вставки `metrika.js` и даты в JSON-LD — те не были частью генератора, а были ручными правками поверх шаблона, которые генератор не знал, что нужно сохранить (родственный, но отдельный класс — см. `memory/facts/regenerator-drops-manual-fields.md`).
4. **Warehouses geocode-фикс уехал в чужой коммит.** 01.08.2026 параллельная сессия сделала `git add -A` до того, как автор фикса геокодера складов успел закоммитить точечно — смысл правки был бы потерян в истории, если бы не восстановлен вручную в `docs/agents/warehouses-geocode-fix-2026-08-01.md`. Формально не «генератор — git add не знает», а обратный вариант того же семейства: чужой широкий `git add -A` подмял узкую генерацию.

## Правило

Каждый скрипт, который пишет файлы на диск (обложки, sitemap, JSON-LD, geojson, любой производный артефакт), обязан явно коммитить **все** свои выходные файлы в том же вызове, а не полагаться на то, что кто-то потом сделает `git add`. Широкий `git add -A`/`git add data/` в общем дереве — сам по себе источник этого класса багов (см. `memory/facts/shared-worktree-git-hygiene.md`) и одновременно то, что временно маскирует проблему №1-2, пока не наступит на чужую незакоммиченную работу.
